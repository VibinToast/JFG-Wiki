# Custom heroes

Everything a mod needs to replace a hero with one of its own: its own movement and physics, its own model, attacks,
health, camera and sounds, while doors, exits, pick-ups, death and the restart stay the game's. These entries came
with **API version 4**; check `jfg_api_version() >= 4` before calling them.

The same helpers suit a custom boss or any mod that moves things by itself: the collision, damage and drawing
entries don't need a hero to be taken over.

## How a custom hero fits together

<Steps>
### Take the hero over

On the first `jfg_on_game_tick`, call `jfg_hero_takeover(1, 1)` (there is no start-up event yet). From then on
`jfg_on_hero_control` fires each tick instead of the game's control code.

### Move it every tick

Read `jfg_input_get`, run your own movement against the level (`jfg_level_triangles` once per level,
`jfg_object_triangles` each tick), and write the hero object's position (+0x0C), velocity (+0x1C) and yaw (+0x00).
Doors, exits, pick-ups, the camera and the enemies' aim all go by them. Heroes face -z at yaw 0.

### Fight

Hit things with `jfg_damage_sphere`; notice hits taken through the hero's health between ticks and
`jfg_object_blast_damage`; find enemies to touch with `jfg_enemies_near`.

### Draw it

Cancel the hero's own model in `jfg_on_object_draw_gfx` and write your own there.

### Borrow the game's hero when it's easier

`jfg_hero_game_control` runs the game's own code for a tick or for as long as you like (aiming and shooting, say) and
gives the hero back afterwards.
</Steps>

<Callout type="warning">
**Things the game's control code did that a taken-over hero still gets:** the follow camera's bookkeeping, the hero's
hit spheres moved with it (so enemies shoot where it is), its track segment kept up to date (so it is drawn), and,
while it is dead (health under 256), the game's own death and restart. **Things it doesn't:** fall damage, the hurt
flash and shake (`jfg_screen_flash`), lava damage, and the gun's position; do those yourself, or hand the hero back.
</Callout>

## Taking a hero over

### jfg_hero_takeover <Status s="built" />

```c
/**
 * @brief  While on, the game's own control code for a hero doesn't run: jfg_on_hero_control fires in its place.
 * @param  character  1 Juno (the only one so far).
 * @param  on         1 to take it over, 0 to give it back.
 * @since  4
 * @note   The mod moves the hero object itself: position +0x0C, velocity +0x1C, yaw +0x00. A dead hero (health under
 *         256) runs the game's code, so death and the restart are the game's own.
 */
void jfg_hero_takeover(int character, int on);
```

### jfg_on_hero_control <Status s="built" />

```c
/**
 * @brief  Each tick a taken-over hero is controlled, in place of the game's code. The controller has been read.
 * @param  hero       The hero's object.
 * @param  frames     Ticks of 1/60 s the tick covers (2 at 30 fps, 1 at 60 fps).
 * @param  character  1 Juno.
 * @since  4
 */
RECOMP_CALLBACK("*", jfg_on_hero_control) void my_hero(void* hero, int frames, int character);
```

### jfg_hero_game_control <Status s="built" />

```c
/**
 * @brief  While on, a taken-over hero runs the game's own control code again: its aim and weapons, its camera and its
 *         moves carry on from where the mod left the hero object.
 * @param  character  1 Juno.
 * @param  on         1: the game's code runs it from this tick; 0: the mod again.
 * @since  4
 * @note   jfg_on_hero_control still fires first each tick, so a mod can switch tick by tick (while the player holds
 *         aim, for instance). When the mod takes the hero back mid-aim, the hero leaves its aim.
 */
void jfg_hero_game_control(int character, int on);
```

### jfg_hero_select_weapon <Status s="built" />

```c
/**
 * @brief  The hero takes its next weapon, or the one before, as the game's weapon buttons do (the weapon list shows).
 * @param  hero       The hero's object.
 * @param  direction  1 next, -1 previous.
 * @since  4
 * @note   While a mod moves a hero, its buttons are the mod's: the mouse wheel changes the weapon this way by itself,
 *         and a weapon changed this way stays when the game's code runs the hero again.
 */
void jfg_hero_select_weapon(void* hero, int direction);
```

### jfg_hero_heads <Status s="built" />

```c
/**
 * @brief  The heads the first player has collected as a hero.
 * @param  character  0 Vela, 1 Juno, 2 Lupus.
 * @param  tribal     1 the tribals' heads, 0 the others'.
 * @since  4
 */
int jfg_hero_heads(int character, int tribal);
```

## Controls

### jfg_input_get <Status s="built" />

```c
/** @brief The first player's controller this tick. */
typedef struct {
    int stick_x, stick_y;    ///< After the game's own handling (and the dual-stick and mouse options)
    int raw_x, raw_y;        ///< The pad's own, -80..80
    unsigned int held;       ///< libultra buttons: A 0x8000, B 0x4000, Z 0x2000, START 0x1000, L 0x20, R 0x10, C 0x0F
    unsigned int pressed;    ///< Pressed this tick
    unsigned int camera_yaw; ///< The camera the hero steers by (0x10000 a turn)
} JfgInput;

/**
 * @brief  The controller as the hero's control reads it this tick.
 * @since  4
 * @note   Ticks can be 1/60 s while your movement steps at 30 Hz: collect presses between your steps, or quick ones
 *         are lost.
 */
void jfg_input_get(JfgInput* out);
```

### jfg_controls_get <Status s="built" />

The N64 buttons tell you what the game would do, not which control was pressed: with the dual-stick layout the
controller's A is the game's jump (C-up). A hero with its own layout reads the physical controls here.

```c
#define JFG_PAD_A      0x0001
#define JFG_PAD_B      0x0002
#define JFG_PAD_X      0x0004
#define JFG_PAD_Y      0x0008
#define JFG_PAD_LB     0x0010
#define JFG_PAD_RB     0x0020
#define JFG_PAD_LT     0x0040 ///< Pulled over half way
#define JFG_PAD_RT     0x0080
#define JFG_PAD_L3     0x0100
#define JFG_PAD_R3     0x0200
#define JFG_PAD_BACK   0x0400
#define JFG_PAD_START  0x0800
#define JFG_PAD_UP     0x1000
#define JFG_PAD_DOWN   0x2000
#define JFG_PAD_LEFT   0x4000
#define JFG_PAD_RIGHT  0x8000

/** @brief The player's controls. */
typedef struct {
    int modern;                        ///< The dual-stick controls are in charge now (Dual Stick or Mouse and Keyboard option, in gameplay)
    int mouse;                         ///< The mouse and keyboard play (the mouse is captured)
    unsigned int buttons;              ///< Physical controls held, JFG_PAD_*
    float left_trigger, right_trigger; ///< 0..1
} JfgControls;

/**
 * @brief  Whether modern controls are on, and the physical controls held as a modern pad.
 * @since  4
 * @note   While the mouse plays, keys and mouse buttons count as pad buttons: Space A, Left Ctrl or C B, F X, R Y,
 *         Q LB, E RB, right mouse button LT, left RT, Left Shift L3, Tab Back, Enter Start, 1-4 the D-pad (up, right,
 *         down, left). With modern on, the right stick and the mouse turn the port's camera, and jfg_input_get's
 *         stick is already turned to it.
 */
void jfg_controls_get(JfgControls* out);
```

<Callout type="info">
While a mod moves a hero, the port's aiming options (Keep the Reticle Centered, aim speed, Jump While Aiming) leave
its controller alone.
</Callout>

## Camera

Two ways: set the camera yourself every tick (`jfg_camera_set`), or set nothing and let the game's camera run, with
the port's dual-stick camera on top when the player uses it. Then move relative to `jfg_camera_get`'s yaw.

### jfg_camera_get <Status s="built" />

```c
/** @brief The camera the hero steers by (the game's angles, 0x10000 a turn). */
typedef struct {
    float x, y, z;
    unsigned int yaw, pitch;
} JfgCameraView;

/**
 * @brief  The camera the hero steers by.
 * @since  4
 * @note   Read while drawing (jfg_on_object_draw_gfx), it is the view on screen, the port's dual-stick camera
 *         included. With d = position - focus: yaw = 0x8000 - atan2(dx, dz), pitch = atan2(dy, |dxz|).
 */
void jfg_camera_get(JfgCameraView* out);
```

### jfg_camera_set <Status s="built" />

```c
/** @brief A camera for this tick. */
typedef struct {
    float x, y, z;    ///< Where it stands
    float fx, fy, fz; ///< What it looks at
    int roll;         ///< 0x10000 a turn
    float fov;        ///< Degrees; 0 = the game's
} JfgCameraSet;

/**
 * @brief  This tick the camera stands here, applied after the game's own camera code.
 * @since  4
 * @note   Set it every tick you want it; the tick you stop, the game's camera carries on from there. While it is set,
 *         the port's camera options (dual-stick and aiming views, FOV) leave the camera alone, the left stick is
 *         given as the pad gives it, and the right stick works as the C buttons.
 */
void jfg_camera_set(const JfgCameraSet* camera);
```

### jfg_camera_set_distance <Status s="built" />

```c
/**
 * @brief  The port's dual-stick camera stands scale times as far out as usual, on top of the player's Camera
 *         Distance option.
 * @param  scale  1 = as usual (0.1 to 10).
 * @since  4
 * @note   Kept until set again: set it back to 1 on a level change.
 */
void jfg_camera_set_distance(float scale);
```

## The level

### jfg_level_triangles <Status s="built" />

```c
/** @brief One of the level's collision triangles. */
typedef struct {
    short v[3][3];         ///< Three corners, level units
    short pad;
    unsigned int flags;    ///< Its batch's flags
    unsigned int texture;
} JfgTriangle;

/**
 * @brief  Copies the level's collision triangles (its render triangles are its collision).
 * @param  out          Where to copy them; NULL only counts.
 * @param  first, max   Which ones: from index first, at most max (copy a big level in chunks).
 * @param  ignore_mask  Leave out batches with any of these flags.
 * @return How many there are in all.
 * @since  4
 */
int jfg_level_triangles(JfgTriangle* out, int first, int max, unsigned int ignore_mask);
```

**Batch flags:** 0x2000 water, 0x8000 damage floor (lava), 0x80000000 kill floor, 0x40000000 ceiling, 0x02000000 /
0x04000000 / 0x08000000 walls for one hero only, 0x400 invisible but solid. Which batches stop a hero is the game's
rule: solid if it has a flag of the hero's include mask (hero data +0x51C), otherwise not if it has a flag of the
ignore mask (+0x518) or 0x880, otherwise solid. Triangles may wind either way: weigh the area facing up against down.

### jfg_level_floor <Status s="built" />

```c
/** @brief A question about the ground at (x, z). */
typedef struct {
    float x, z;
    unsigned int mask;   ///< Batches with one of these flags (0x2000 for water)
    float y;             ///< out: its height
    unsigned int flags;  ///< out: its batch's flags; 0 = none found
} JfgFloor;

/**
 * @brief  The first triangle under a point whose batch has one of mask's flags.
 * @since  4
 * @note   A hero swims once it is 48.5 units below the water surface.
 */
void jfg_level_floor(JfgFloor* q);
```

### jfg_object_triangles <Status s="built" />

```c
/** @brief A sphere to look in. */
typedef struct {
    float x, y, z, radius;
    void* source;          ///< An object to leave out (your hero)
} JfgNear;

/** @brief A solid object's triangle, world space. */
typedef struct {
    float v[3][3];
    unsigned int flags;    ///< Its batch's (as JfgTriangle's)
    void* object;
} JfgObjectTriangle;

/**
 * @brief  The collision triangles of the solid objects (crates, doors, lifts, props) whose box overlaps a sphere.
 * @return How many there are (at most max copied).
 * @since  4
 * @note   They move: call it each tick.
 */
int jfg_object_triangles(const JfgNear* query, JfgObjectTriangle* out, int max);
```

## Damage

Health is 256 a unit; the heroes have 0x2200 when full and die below 0x100.

### jfg_damage_sphere <Status s="built" />

```c
#define JFG_TARGET_HEALTH 1 ///< Objects with health: enemies, heroes
#define JFG_TARGET_PROPS  2 ///< Breakable solid objects: crates, props

typedef struct {
    float x, y, z, radius;
    int damage;            ///< 256 = one unit
    void* source;          ///< Not hurt (your hero)
    int targets;           ///< JFG_TARGET_*, 0 = both
    int props_hit;         ///< out: breakables hit
} JfgDamageSphere;

/**
 * @brief  Damages every object with health whose hit centre is in the sphere, and the breakables it touches.
 * @return How many objects with health it hit.
 * @since  4
 * @note   Enemies react to the health change themselves (they flinch and die the usual way). Health stops at 0; for an
 *         overkill that bursts the enemy, set its health to -0x8000 with jfg_object_set_health. A stock crate takes
 *         about 3 units. Call it once per attack, not every tick of it.
 */
int jfg_damage_sphere(JfgDamageSphere* sphere);
```

### jfg_objects_near, jfg_enemies_near, jfg_enemy_type <Status s="built" />

```c
typedef struct {
    void* object;
    float x, y, z;   ///< Its hit centre
    int health;
} JfgNearObject;

typedef struct {
    void* object;
    float x, y, z;   ///< Its hit centre
    float radius;    ///< Its hit radius
    int health;      ///< 0 or less: dying (still there until removed)
    int type;        ///< As jfg_enemy_type
    int tribal;      ///< 1: a tribal to rescue, not an enemy
} JfgEnemy;

/**
 * @brief  objects_near: objects with health whose hit centre is in a sphere. enemies_near: squad members whose hit
 *         sphere overlaps it, dying ones too. Both nearest first, leaving out query->source.
 * @return How many there are (at most max copied).
 * @since  4
 */
int jfg_objects_near(const JfgNear* query, JfgNearObject* out, int max);
int jfg_enemies_near(const JfgNear* query, JfgEnemy* out, int max);

/**
 * @brief  A squad member's type (its object id, the same for its whole squadron); -1 for anything else.
 * @since  4
 */
int jfg_enemy_type(void* object);
```

A squad member bursts on its next update when its health falls to -(its full health / 8) or lower (between -2 and
-10 units). A dying one still bursts from a further big blow.

## Drawing

### jfg_on_object_draw_gfx <Status s="built" />

```c
/** @brief An object about to be drawn, with the game's drawing cursors. */
typedef struct {
    void* object;
    void** gfx;   ///< Gfx**: write commands here (advancing it)
    void** mtx;   ///< Mtx**
    void** vtx;   ///< Vertex**
    int cancel;   ///< 1: skip the game's own drawing of it
} JfgObjectGfx;

/**
 * @brief  An object is about to be drawn (after jfg_on_object_draw): write your own commands, or cancel the game's.
 * @since  4
 * @note   The game's camPushModelMtx / camPopModelMtx and texDPTextureX can be called with these cursors. Keep the
 *         transform you push at a fixed address: frame interpolation tells an object's matrices apart by it. The
 *         game's display lists are Rare's own format (10-byte coloured vertices, 16-byte triangles with their own
 *         texture coordinates), not F3D. Textures need to be in game memory (mmAlloc).
 */
RECOMP_CALLBACK("*", jfg_on_object_draw_gfx) void my_draw(JfgObjectGfx* draw);
```

A taken-over hero's gun is a separate object: the hero object's +0x60 points to its weapon holder, whose +4 is the
gun object. Cancel its draw in `jfg_on_object_draw` unless the game's code is running the hero.

/**

## Sound

### jfg_sound_play, jfg_sound_loop, jfg_sound_set, jfg_sound_stop <Status s="built" />

The mod's own sound effects: OGG or 16-bit PCM WAV files shipped as the mod's additional files and named in a
`jfg_sounds.json` among them.

```json
{ "sounds": { "jump": "jump.ogg", "engine": "engine_loop.wav" } }
```

```c
/**
 * @brief  Plays a sound once (play) or until stopped (loop).
 * @param  name    Its name in jfg_sounds.json.
 * @param  volume  1 = as recorded.
 * @param  pan     -1 left to 1 right.
 * @param  pitch   1 = as recorded, 2 an octave up.
 * @return A voice, 0 if there's no such sound.
 * @since  4
 * @note   Mixed after the music, at the player's sound effects volume.
 */
int  jfg_sound_play(const char* name, float volume, float pan, float pitch);
int  jfg_sound_loop(const char* name, float volume, float pan, float pitch);

/**
 * @brief  Changes a playing voice (to follow a moving source, say).
 * @return 1 while it plays, 0 once it has ended.
 * @since  4
 */
int  jfg_sound_set(int voice, float volume, float pan, float pitch);
void jfg_sound_stop(int voice);
```

<Callout type="info">
The packer stores additional files without their folders; a file named with a folder in `jfg_sounds.json` is also
found by its file name alone.
</Callout>

## Mod options

Not part of `jfg_api.h`, but a custom hero usually wants them: options on the mod's **Configure** page in the Mods
menu. List them in `mod.toml`:

```toml
[[manifest.config_options]]
id = "camera_distance"
name = "Camera distance"
description = "How far out the camera stands."
type = "Enum"
options = [ "100%", "150%", "200%" ]
default = "150%"
```

and read them whenever you need them (an Enum gives its option's index):

```c
RECOMP_IMPORT("*", unsigned long recomp_get_config_u32(const char* key));

float distance = (float[]){ 1.0f, 1.5f, 2.0f }[recomp_get_config_u32("camera_distance")];
```
