# Weapons

The heroes' weapons from code: **new weapons of your own**, who has what and how much ammo, your own shots and
effects, HUD icons and kill credit. How the game's weapon table works and what each field does is in
[Weapons](/api/weapons). Full walk-throughs: [A thrown weapon](/tutorials/thrown-weapon), and
[A charged weapon](/tutorials/charged-weapon) for one that charges, fires its own blast and has its own gun in the
hand.

## How new weapons work

The game has 16 weapon slots: 0-14 are the heroes' weapons and 15 is a cut proximity mine. There is no room for more
in the game's own data, so **slot 15 is a carrier**: Jet Force Gemini: Recompiled keeps every new weapon itself, and
whichever one is in the hero's hand borrows slot 15. Its ammo, its row of stats and its name are copied in, so the
game's own code shows, aims, fires and throws it.

- **Any number of weapons.** Each registers **by name** (`"mymod:hose"`) and gets an id for this run: 16, 17, ... in
  the order mods register. Keep the name, not the number: another player's mod list gives other numbers.
- **Switching.** Next / previous weapon steps through every weapon the hero owns, the new ones included.
- **Firing.** A new weapon fires as its **host**, a stock weapon (its shot, aim and timing), unless your
  `jfg_on_weapon_fire` cancels the shot and makes your own.
- **Charging.** A weapon whose stats row charges (the plasma shotgun's, `row_from` 3: hold fire, let go) charges at
  the plasma shotgun's rate, and `jfg_on_weapon_hud` reports its charge, so mods' HUDs fill its charge bar.
  `jfg_on_weapon_fire`'s `charge` is the charge it was let go at. The game's own charge glow, the charge pips in the
  aim and the rumble stay the plasma shotgun's: show your own (a sound, an object at the muzzle).
- **In the hand.** A new weapon shows its own model with `jfg_weapon_set_held_model`; without one the hero holds
  what the grenades show (an empty hand for Vela and Juno, a grenade for Lupus).
- **Saving.** Owned new weapons and their ammo are saved with the save file, by name. A weapon whose mod is removed
  stays in the file and comes back when the mod does.
- **Randomizers.** All weapons, stock and new, are in one list (`jfg_weapon_count`, `jfg_weapon_info`); any weapon
  pickup can be pointed at any weapon (`jfg_weapon_pickup_set`).

## New weapons

### jfg_weapon_register <Status s="built" />

```c
/** @brief A new weapon. */
typedef struct {
    const char* name;         ///< Unique, "mod_id:weapon" (no spaces)
    const char* display;      ///< Its name in the HUD and pick-up messages ("" = name)
    const char* ammo_display; ///< Plural, for "more ammo" messages ("" = display)
    int host;         ///< The stock weapon (0-14) whose shot it fires and how it's held; -1 the default laser bolt
    int charge;       ///< The charge given to the host's shot (a mine's type), -1 as it is
    int thrown;       ///< 1: thrown (the hero's throw animation), 0: as the host
    int row_from;     ///< The stock weapon whose stats row it uses (refire, speed, spread, damage): 0-14
    int max_ammo;     ///< -1 = the row's
    int start_ammo;   ///< Given with the weapon, -1 = the row's
    int pickup_ammo;  ///< A pickup of it when owned, -1 = the row's
} JfgWeaponDef;

/**
 * @brief  Registers a new weapon.
 * @return Its id for this run (16 and up; the same id again for a name registered before), or -1.
 * @since  6
 * @note   Register on your first jfg_on_game_tick. A weapon saved in the file in play is given back as it registers.
 *         A thrown weapon whose row has no throw delay gets the grenade's (the hero lets go 26 ticks into the throw).
 */
int jfg_weapon_register(const JfgWeaponDef* def);
```

### jfg_weapon_find, jfg_weapon_count, jfg_weapon_info <Status s="built" />

```c
typedef struct {
    char name[48];    ///< As jfg_weapon_find takes it
    char display[40]; ///< The name to show (stock weapons: in the language shown)
    int modded;       ///< 1 for a mod's weapon
    int host;         ///< Stock weapons: their own number
    int thrown;       ///< -1: the game's own rule (stock weapons)
    int max_ammo;
} JfgWeaponInfo;

/**
 * @brief  Weapons by name ("stock:pistol" .. "stock:cluster_bombs", "port:proximity_mine", "mod_id:weapon"); how many
 *         ids there are (0 .. count - 1 are all weapons); one weapon's details.
 * @return find: the id or -1; info: 1, or 0 for no such weapon.
 * @since  6
 * @note   Show a weapon's name with info.display, for any id. The game's own texts only cover slots 0-15.
 */
int jfg_weapon_find(const char* name);
int jfg_weapon_count(void);
int jfg_weapon_info(int id, JfgWeaponInfo* out);
```

### jfg_weapon_set_icon, jfg_weapon_set_icon_image <Status s="built" />

```c
/**
 * @brief  A new weapon's HUD icons. set_icon: a 2D sprite of your pack (about 32 x 22, as the game's), shown in the

 *         picture (at most 512 x 512, colours 0xRRGGBBAA, copied), drawn sharp at the window's resolution wherever a

 * @param  sprite  Its number this run: jfg_asset_number("mod_id:sprite name"); -1 gives slot 15's own back.
 * @since  6
 * @note   Make the sprite with jfgformats' sprites.write (see the tutorial). jfg_hud_weapon_icon takes any weapon id.
 */
void jfg_weapon_set_icon(int id, int sprite);
void jfg_weapon_set_icon_image(int id, int w, int h, const unsigned int* rgba);
```

### jfg_weapon_set_held_model <Status s="built" />

```c
/**
 * @brief  A new weapon's model in the hero's hand while it is held: a model of your pack, drawn on the hand where the
 *         game draws its own guns, at their size and axes. Its barrel point is where the weapon's shots leave.
 * @param  model  Its number this run: jfg_asset_number("mod_id:model_gun"); -1 = none of its own (the hero then
 *                holds what the grenades show: an empty hand for Vela and Juno, a grenade for Lupus).
 * @since  6
 * @note   Call it once, after jfg_weapon_register. Only for new weapons (16 up).
 */
void jfg_weapon_set_held_model(int id, int model);
```

What the model must be:
- **Static**: one mesh, no joints or animation. Nothing poses a held gun.
- **In the hand's frame**: the **grip at the origin** (that point sits in the hero's hand), the barrel running
  forward, down and out toward about **(0.75, -0.36, -0.55)** in game axes (Y up), as the game's own hand guns.
  The game draws it with the hand's own turn, so this odd angle is what comes out straight in the hand.
- **About 70 units** from the grip to the muzzle, in the hero's own units: Vela's guns are 66-78 long; Juno's are
  about 1.2 times bigger, and one model is used for both. The object's scale isn't used.
- **A barrel point**: an empty named **`barrel`** at the muzzle in the `.glb` (jfgformats 0.7.1 or newer). Shots,
  and the barrel position the game keeps for the hero, leave from there. Without one the barrel stays where the
  last gun left it.
- **Lupus** carries his guns on his back, pointing forward along his body. A model made for Vela's hand looks off on
  him: check it, or make the weapon one he doesn't use.
- White vertex colours (the game lights it by them) and your light painted into the textures.

The [A charged weapon](/tutorials/charged-weapon#put-a-gun-in-the-hand) tutorial builds one in Blender.

## Firing and kills

### jfg_on_weapon_fire <Status s="built" />

```c
typedef struct {
    int weapon;     ///< Any id, new ones included
    int character;  ///< 0 Vela, 1 Juno, 2 Lupus
    void* hero;     ///< The hero's object
    int charge;     ///< The plasma shotgun's charge as the game keeps it
    int cancel;     ///< Set 1: the game fires nothing (fire your own)
    int take_ammo;  ///< With cancel: 1 (default) uses one ammo, 0 none
} JfgWeaponFire;

/**
 * @brief  The first player's hero is about to fire a shot, or let go of a throw, before the game makes it.
 * @since  6
 * @note   For a thrown weapon this comes as the hero lets go, not on the button press.
 */
RECOMP_CALLBACK("*", jfg_on_weapon_fire) void my_fire(JfgWeaponFire* f);
```

### jfg_weapon_credit <Status s="built" />

```c
/**
 * @brief  Credits what your weapon hurts: if the victim (a squad member) dies within ticks, jfg_on_kill reports your
 *         weapon and the shooter, so kill feeds and stats show it.
 * @param  ticks  1/60 s, at most 600. Dying enemies may lie down and bleed out first: credit generously.
 * @since  6
 * @note   Your weapon hurts in its own ways (health, blasts, explosions), which the game counts under whatever is in
 *         hand. Credit as you hurt; call again to renew.
 */
void jfg_weapon_credit(void* victim, int weapon, void* shooter, int ticks);
```

## Objects and effects for weapons

### jfg_spawn, jfg_asset_number <Status s="built" />

```c
typedef struct {
    int object;          ///< An object id: a stock one, or your pack's object type (jfg_asset_number)
    float x, y, z;
    float vx, vy, vz;    ///< Units a tick (needs a physics block in its definition)
    int yaw;             ///< 0-0xFFFF
} JfgSpawn;

/**
 * @brief  An object at a point, as a shot is made (it goes with the level). With a physics block in its definition it
 *         flies at vx, vy, vz and falls, bounces and comes to rest by the game's own physics.
 * @return The object, or NULL.
 * @since  6
 */
void* jfg_spawn(const JfgSpawn* spawn);

/**
 * @brief  The number your pack's appended entry or object type got this start ("mod_id:append name", as your
 *         jfg_assets.json names it), -1 if no loaded mod adds it. An object type's number is the object id to spawn.
 * @since  6
 */
int jfg_asset_number(const char* name);
```

### jfg_explosion, jfg_blast, jfg_shockwave <Status s="built" />

```c
typedef struct { int type; float x, y, z; void* owner; } JfgExplosion;
typedef struct { float x, y, z, radius, damage, seconds; void* owner; } JfgBlast;
typedef struct { float x, y, z, inner, outer, inner_speed, outer_speed; int hold, fade; } JfgShockwave;

/**
 * @brief  explosion: one of the game's explosions with its look, sound and damage (type 0 the grenade's, 4 under
 *         water). blast: damage only, strongest at the middle and less out to the radius, fading over the seconds
 *         (256 a unit of health; 16 at a time). shockwave: the game's flat ring, its radii growing by their speeds
 *         (negative: shrinking), held, then faded (radii and speeds within -100..100).
 * @since  6
 * @note   The game's explosions hurt the heroes too, as grenades do.
 */
void jfg_explosion(const JfgExplosion* explosion);
void jfg_blast(const JfgBlast* blast);
void jfg_shockwave(const JfgShockwave* wave);
```

## Stats

### jfg_weapon_stat_get, jfg_weapon_stat_set <Status s="partial" />

A weapon slot's damage, refire, speed and spread from C. Today a new weapon takes them from its `row_from` slot, and
a pack sets slots 0-14 from Lua (`jfg.weapon(n, fields)`, `jfg.weapon_stats(n)`, see [Weapons](/api/weapons)); the C
helpers are planned:

```c
/** @target 7 */
int  jfg_weapon_stat_get(int weapon, int field);
void jfg_weapon_stat_set(int weapon, int field, int value);
```

## Planned

- **A model per hero.** One held model serves all three heroes; Lupus's back mount would want its own.
- **The game's charge glow, aim pips and rumble for new charged weapons.** Today they stay the plasma shotgun's.
- **`jfg_on_weapon_select`, `jfg_on_projectile_spawned`, `jfg_on_projectile_hit`.** Until then, poll
  `jfg_hero_weapon` and track your own shots.
- **The hero's aim as a helper.** The tutorial reads it from the hero's control data.

## Example: a weapon that isn't thrown

A rapid green laser on the machine gun's timing, firing Floyd's bolt instead of the game's shot, with its kills
credited to it (a bigger one, charged, with a blast of its own, is [A charged weapon](/tutorials/charged-weapon)):

```c
static int laser = -1;

RECOMP_CALLBACK("*", jfg_on_game_tick) void setup(int frames) {
    if (laser >= 0) return;
    JfgWeaponDef d = { "mymod:green_laser", "Green Laser", "Green Laser Cells", 2, -1, 0, 2, 200, 100, 50 };
    laser = jfg_weapon_register(&d);
}

RECOMP_CALLBACK("*", jfg_on_weapon_fire) void fire(JfgWeaponFire* f) {
    if (f->weapon != laser) return;
    const float* p = (const float*)((char*)f->hero + 0x0C);           // the hero's position
    const unsigned short yaw = *(unsigned short*)f->hero;               // facing (see the tutorial for the aim)
    const float dx = -sinf(yaw * 3.14159265f / 32768.0f), dz = -cosf(yaw * 3.14159265f / 32768.0f);
    JfgBolt b = { p[0], p[1] + 30, p[2], p[0] + dx * 500, p[1] + 30, p[2] + dz * 500, 2, 35.0f, 20, f->hero, -1 };
    jfg_fire_bolt(&b);
    f->cancel = 1;   // no game shot; one ammo used
}
```

<Callout type="info">
Mods have no maths library: write your own `sinf` / `cosf` (a short approximation is enough), as the tutorial does.
Kills by the bolt are counted by the game under the slot it picks; when your shot hurts things itself (setting
health, a blast), credit them with `jfg_weapon_credit` so kill feeds show your weapon.
</Callout>
